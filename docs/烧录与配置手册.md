## 1. U 盘里是什么

烧录后的 U 盘是四个分区的 GPT 磁盘,BIOS 与 UEFI 机器都能直接引导:

```
p1  bios-grub   1 MB      无文件系统          grub 引导核心(BIOS 用)
p2  ESP         2 GiB     FAT32,卷标 ESP      grub + 内核 + initramfs
p3  config-2    256 MiB   FAT32,卷标 config-2  deploy.yaml + agent 配置 + 结果回写
p4  ipa-images  剩余空间  FAT32,卷标 ipa-images 待装系统镜像文件
```

启动后 initramfs 内的本地编排器(orchestrator)依次完成:

1. **等待 IPA 就绪** —— 本机 ironic-python-agent 起在 `127.0.0.1:9999`,不连任何外部 API;
2. **读配置、起镜像服务** —— 挂载 `config-2` 读 `deploy.yaml`;把 `ipa-images` 目录用 HTTP 服务在
   `127.0.0.1:8484`(IPA 镜像下载只认 http/https);
3. **写盘** —— 按需擦盘 → `standby.prepare_image` 下载镜像、校验 sha256、写入目标盘、写 configdrive
   → 分区镜像再调 `image.install_bootloader` 装 grub(BIOS/UEFI 自动识别);
4. **回写结果、关机** —— `deploy-result.json` 写回 `config-2` 分区,按配置关机,装机完成即可拔盘。

## 2. 烧录 U 盘

镜像文件:`usb-image.raw`(默认 8 GB,整盘 dd)。**写入会清空整块 U 盘**,先认准设备名。

### 步骤

1. **认盘**:插上 U 盘,用容量对号入座 —— 下例中 `sdb` 是 U 盘,`sda` 是系统盘:

   ```
   lsblk -d -o NAME,SIZE,MODEL,TRAN
   # NAME   SIZE  MODEL               TRAN
   # sda    85G   VMware Virtual disk sata
   # sdb    14.6G SanDisk Ultra       usb
   ```

   > ⚠️ **危险操作**:`of=` 写错设备会直接毁掉那块盘上的全部数据,包括系统盘。
   > 写之前用 `lsblk` 或 `dmesg | tail` 再确认一次。

2. **写入(Linux)**:

   ```bash
   # 假设 U 盘是 /dev/sdb —— 换成你确认的设备名
   dd if=usb-image.raw of=/dev/sdb bs=4M conv=fsync status=progress
   ```

   `conv=fsync` 确保落盘后才返回;别提前拔盘。

3. **写入(Windows)**:Rufus 选镜像后以 **DD 模式** 写入(弹出提示时选 DD),或用 balenaEtcher。

4. **校验(可选)**:

   ```bash
   # 读回与镜像逐字节比对(U 盘读一次,约几分钟)
   SIZE=$(stat -c %s usb-image.raw)
   cmp -n "$SIZE" usb-image.raw /dev/sdb && echo 写入一致
   ```

5. **放入镜像文件**:把待装系统镜像拷进第 4 分区(文件管理器里叫 `ipa-images`):

   ```bash
   mount /dev/sdb4 /mnt
   cp jammy-server-cloudimg-amd64.img jammy-server-cloudimg-amd64.img.sha256 /mnt/
   cp configdrive.iso /mnt/          # 可选:cloud-init 配置盘
   umount /mnt
   ```

   > p4 是 FAT32,单文件上限 4 GiB。镜像更大时,构建时把该分区改成 ext4(见 §8)。

## 3. 目标机要求

| 要求 | 说明 |
|---|---|
| 内存 ≥ 3 GB | initramfs 解包后约 1.4 GB,2 GB 机器会卡死在解包阶段 |
| ≥ 1 块非可移动盘 | 由编排器选定装机目标盘:优先 `deploy.yaml` 的 `target.device`,否则排除 U 盘后取最大的非可移动盘(见 §4) |
| BIOS 或 UEFI | 双模式引导均已验证;UEFI 请先关闭 Secure Boot |
| 无需网络 | 镜像、配置全在 U 盘上,整机流程只走 127.0.0.1 |

开机选择从 USB 启动(BIOS 里表现为 USB-HDD / U 盘型号名;UEFI 里是 `UEFI: <U 盘名>`)。
grub 菜单 3 秒后自动进入装机。

## 4. deploy.yaml 配置

装机行为全部由 `config-2` 分区上的 `deploy.yaml` 驱动。
改配置 = 改这个文件 + 拷回分区,**无需重做 U 盘**。

### 完整示例(当前验证通过的真实配置)

```yaml
# 目标磁盘策略(可选)
target:
  # device: /dev/sda        # 显式指定装机盘;留空 = 自动选择(排除 U 盘后取最大非可移动盘)

# 待装镜像:放在 ipa-images 分区
image:
  # ⚠️ Ubuntu 云镜像必须用 generic 变体(如 jammy-server-cloudimg-amd64.img)。
  # -disk-kvm 变体是 virtio 精简内核,无 LSI SCSI 等驱动,在 VMware 上装完
  # 启动会黑屏假死(内核认不到虚拟盘)。
  file: jammy-server-cloudimg-amd64.img   # 镜像文件名(相对 ipa-images 根目录)
  checksum_file: jammy-server-cloudimg-amd64.img.sha256   # 缺省为 <file>.sha256
  image_type: whole-disk       # whole-disk(整盘镜像,自带引导) | partition(分区镜像,装完补 grub)
  disk_format: qcow2           # qcow2 | raw
  # stream_raw: true           # 仅 raw:流式直写,不落中间文件

erase:
  enabled: false               # true = 先对目标盘做 erase_devices(ATA 安全擦除,耗时长)

configdrive:                   # 可选:cloud-init configdrive(NoCloud)
  file: configdrive.iso        # ipa-images 里的 ISO 文件(volid 需为 cidata)
  # base64: H4sIABAAA...       # 或直接给 gzip+base64 编码的内容

post:
  shutdown: true               # 装机完成后自动关机;false 则停在装机完成的控制台
  result_file: deploy-result.json   # 结果写回 config-2 分区
```

### 字段速查

| 字段 | 必填 | 说明 |
|---|---|---|
| `target.device` | 否 | 显式指定装机盘(如 `/dev/sda`)。缺省自动选:排除 U 盘所在盘后,取最大的非可移动盘 |
| `image.file` | 是 | 镜像文件名,必须存在于 ipa-images 分区根目录 |
| `image.disk_format` | 否 | `qcow2`(默认)/ `raw` |
| `image.image_type` | 否 | `partition`(默认)/ `whole-disk`。partition 镜像装完自动 chroot 装 grub;`whole-disk` 跳过 bootloader 步骤 |
| `image.checksum_file` | 否 | 缺省 `<image.file>.sha256`。兼容两种格式:`sha256sum` 输出,以及 Windows PowerShell `Get-FileHash` 表格输出(含 UTF-16 BOM / UTF-8 BOM 文件均可读) |
| `image.stream_raw` | 否 | raw 镜像流式写盘开关 |
| `erase.enabled` | 否 | 装机前擦盘(ATA secure erase 优先)。重装机、处理旧盘建议开 |
| `configdrive.file` / `configdrive.base64` | 否 | configdrive 来源:ISO 文件名或 gzip+base64 内容串(见下方说明) |
| `post.shutdown` | 否 | 默认 `true`:成功后关机。首次调试可设 `false` 留在控制台看日志 |

校验文件生成方式:

```bash
# Linux
sha256sum jammy-server-cloudimg-amd64.img > jammy-server-cloudimg-amd64.img.sha256
```

```powershell
# Windows PowerShell(编排器同样兼容 Get-FileHash 的表格输出)
Get-FileHash -Algorithm SHA256 jammy-server-cloudimg-amd64.img > jammy-server-cloudimg-amd64.img.sha256
```

> **configdrive 格式注意**:IPA 侧对 configdrive 内容先 base64 解码再 gunzip。
> 填 `configdrive.file` 时编排器会自动把 ISO 读入内存做 gzip+base64 后传给 IPA,
> 直接填裸 ISO 的 URL 或未压缩 base64 会报 `Not a gzipped file`。

### 生成 configdrive.iso 的工具

`tools/` 下有两个等价的 NoCloud 配置盘生成工具(创建用户 + 密码 + SSH 密码登录,
**支持静态 IP 与 bond 网络**),任选其一:

- **Python 版** `tools/make-configdrive.py`:依赖 python3 + genisoimage(配网络时需
  PyYAML);独有 `--network-config` 透传,支持 VLAN 等任意 netplan 拓扑:

  ```bash
  python3 tools/make-configdrive.py --user enrigin --password enrigin \
      --hostname enrigin-node --out configdrive.iso

  # 静态 IP / bond 示例
  python3 tools/make-configdrive.py --user enrigin --password enrigin \
      --bond bond0 --bond-slaves eth0,eth1 --bond-mode active-backup \
      --ip 10.0.0.5/24 --gateway 10.0.0.1 --dns 8.8.8.8
  ```

- **Go 版** `tools/go/make-configdrive/`(`go build -o make-configdrive main.go`
  出静态二进制,**零运行时依赖**):参数一致,适合没有 Python/ISO 工具的环境。

不传网络参数 = 默认第一块网卡 DHCP;复杂拓扑(VLAN、多网段等)用 Python 版的
`--network-config <netplan.yaml>` 透传。

**详细用法见 [configdrive-使用说明.md](configdrive-使用说明.md)。**
生成后拷到 IPA-IMAGES 分区根目录即可;改账号密码或网络只需重跑本工具,无需重做 U 盘。

### 装机目标盘的选择

编排器(而非 IPA)负责选盘,写入提示文件后由 IPA 的补丁优先采用:

1. `deploy.yaml` 里 `target.device` 显式指定 → 直接使用;
2. 否则排除 U 盘本身(按 `config-2` / `ipa-images` 分区所在盘识别)——
   standalone 模式的 IPA 原生逻辑是"取最大的盘",不会排除引导 U 盘,会把 U 盘当装机盘;
3. 在剩余磁盘里取最大的非可移动盘;一块盘都没有则报错拒绝装机。

改配置后把文件放回 p3:

```bash
mount /dev/sdb3 /mnt
cp deploy.yaml /mnt/
umount /mnt
```

## 5. agent 高级配置(可选)

`config-2` 分区的 `etc/ironic-python-agent.d/` 目录会由 `usb-provision-config.service`
在 IPA 启动前整体拷入 ramdisk,作为 IPA 的 `--config-dir` —— 可以在这里下发任意 IPA 配置,
例如打开 debug 日志:

```
etc/
└── ironic-python-agent.d/
    └── agent.conf        # 文件名任意,INI 格式
```

```ini
[DEFAULT]
debug = True
# listen_port = 9999        # 默认即 9999
# 其他 IPA 支持的配置项均可放这里
```

### agent_token(预共享鉴权)

新版 IPA 对命令端点(`POST /v1/commands/`)强制校验 `agent_token`,而 standalone 模式下
没有 Ironic 下发 token —— 因此采用**两侧预共享**:

- IPA 侧:上面 `agent.conf` 里的 `agent_token = <值>`(烧录时由 `make-usb.sh` 自动写入
  config-2,并且同一值已直接烧进 initramfs 作为兜底);
- 编排器侧:`orchestrator.py` 的 `AGENT_TOKEN` 常量,请求 URL 带 `?agent_token=<值>`。

两边必须一致,否则所有命令返回 `401 Token invalid`。更换 token 时三处同步:
`orchestrator.py` 常量、config-2 的 `agent.conf`、构建脚本 `make-usb.sh`。
ramdisk 内置兜底会在 USB 枚举慢、config-2 拷贝超时时生效 —— 无它,IPA 无 token 启动
会导致全部命令 401。

> **与原生机制的区别**:没有使用 IPA 的 `boot_method=vmedia` 配置拷贝 ——
> 该机制会排除含分区的设备,对分区式 U 盘不生效,故由独立 systemd 服务在 IPA 启动前完成拷贝
> (服务内含 30 秒轮询等待 USB 枚举)。

## 6. 结果与取盘

无论成败,编排器都把结果写回 `config-2` 分区的 `deploy-result.json`。
装机完成后关机、拔盘,插回任意机器即可读取:

```json
// 成功(整盘镜像 whole-disk:root_uuid 为 null 是预期行为)
{
  "status": "SUCCEEDED",
  "image": "jammy-server-cloudimg-amd64.img",
  "root_uuid": null
}

// 成功(分区镜像 partition:返回目标根分区)
{
  "status": "SUCCEEDED",
  "image": "rootfs.qcow2",
  "root_uuid": "9f4b0c2e-18d7-4a55-b1a2-3c5f6e8d9a01"
}

// 失败
{
  "status": "FAILED",
  "error": "镜像文件不存在: /run/usb-provision/images/rootfs.qcow2"
}
```

Linux 上查看:`mount /dev/sdb3 /mnt && cat /mnt/deploy-result.json`;Windows 下该分区能直接双击打开。

> 全过程日志同时输出到串口 `ttyS0,115200` 与本机控制台;带串口的目标机接上后可实时观察进度。

## 7. 排障

### U 盘起不来

| 现象 | 原因与处理 |
|---|---|
| BIOS 不认 U 盘 | 换 USB 2.0 口;部分老 BIOS 只认 USB-HDD 模式,在启动项里选 U 盘型号名 |
| UEFI 启动菜单里没有 | 确认选带 `UEFI:` 前缀的项;Secure Boot 需关闭(ESP 里的 grub 未签名) |
| grub 进菜单后黑屏 | 接串口(ttyS0 115200)看输出;绝大多数为目标机内存不足(§3) |
| 内核解包阶段卡死 | 内存 < 3 GB:541 MB initramfs 解包后约 1.4 GB,不足时静默卡死 |

### deploy-result.json 为 FAILED

| error 内容 | 处理 |
|---|---|
| `镜像文件不存在: …` | ipa-images 分区里没有 deploy.yaml 指定的文件,或文件名拼写不一致 |
| `校验文件不存在: …` | 缺 `<file>.sha256`,或用 `image.checksum_file` 指定实际名字 |
| `校验文件里找不到 sha256 哈希: …` | 校验文件内容异常;确认里面有一个 64 位十六进制哈希(sha256sum 或 Get-FileHash 输出均可) |
| `IPA 命令 … 失败: HTTP 401: Token invalid` | 两侧 agent_token 不一致(§5);确认 config-2 的 `etc/ironic-python-agent.d/agent.conf` 与编排器常量相同 |
| `Not a gzipped file` | configdrive 内容格式错:IPA 要求 gzip+base64。用 `configdrive.file` 指定 ISO(编排器会自动编码),勿传裸 ISO 的 URL |
| `无法从 prepare_image 结果解析 root_uuid` | IPA 返回消息格式变化;查串口日志中 prepare_image 的原始输出 |
| `除 U 盘(…)外找不到可用磁盘,拒绝自动选盘` | 目标机只有 U 盘一块盘;接上目标硬盘,或在 deploy.yaml 用 `target.device` 显式指定 |
| `等待 IPA API 超时` | IPA 服务没起来:串口里查 `ironic-python-agent.service` 状态;确认 agent 配置(§5)无语法错误 |

### 装机成功,但装好的系统启动黑屏/假死

部署本身成功了(`deploy-result.json` 为 SUCCEEDED),但重启后屏幕停在 grub 提示
(如 `GRUB_FORCE_PARTUUID set, initrdless boot failed. Attempting with initrd.`)之后
再无输出 —— SSH 也连不上。

**原因**:Ubuntu 云镜像用了 `-kvm` 变体(如 `jammy-server-cloudimg-amd64-disk-kvm.img`)。
该变体是为 KVM virtio 定制的精简内核,没有 LSI Logic SCSI(FUSION/MPT)等 VMware
常用虚拟控制器的驱动,目标盘对内核"不存在";镜像自带的 initrdless 引导失败后回退
initrd,initramfs 里同样没有驱动,启动死在那里,而应急输出全在串口(ttyS0),屏幕全黑。

**处理**:换成 **generic 变体**(如 `jammy-server-cloudimg-amd64.img`),通用内核
`CONFIG_ATA_PIIX=y`(IDE 内置),initramfs 里 ahci / mptspi / mpt3sas / vmw_pvscsi / nvme
全有,IDE / SATA / LSI SCSI / PVSCSI / NVMe 均可引导。建议同时删掉镜像里的
`/etc/default/grub.d/40-force-partuuid.cfg` 并重新生成 grub.cfg(在 chroot 里执行
`grub-mkconfig -o /boot/grub/grub.cfg`),消除 initrdless 引导的 panic 重启。
改完镜像必须重算 sha256(`sha256sum <file> > <file>.sha256`)并同步到 p4。

> 顺带说明:cloud 镜像内核参数为 `console=tty1 console=ttyS0`,串口在后,systemd 的
> 用户态输出走串口;VGA 上内核滚屏正常、有 tty1 登录提示。看不到输出时优先按上面
> 排驱动问题,而不是等控制台。

### QEMU 预验证(可选)

写盘前可先在带 QEMU 的机器上空盘试跑:

```bash
# BIOS 模式
qemu-system-x86_64 -m 4096 -drive format=raw,file=usb-image.raw -nographic

# UEFI 模式
qemu-system-x86_64 -m 4096 -drive format=raw,file=usb-image.raw \
    -bios /usr/share/ovmf/OVMF.fd -nographic
```

> **注意**:无 KVM 的纯 TCG 仿真会非常慢,且部分阶段可能卡在 udev 设备扫描 ——
> 那是仿真环境的限制,不代表真机行为。guest 内存给足 3 GB 以上。

## 8. 构建链参考

需要自己改 initramfs、加驱动或换 grub 配置时,从源码重建:

```
usb-provision/
├── deploy.yaml                      # 配置示例(烧录时拷入 config-2)
└── build/
    ├── Dockerfile                   # 构建环境(Ubuntu 22.04 + diskimage-builder)
    ├── build-ramdisk.sh             # 产出 ipa-usb.{kernel,initramfs}
    ├── make-usb.sh                  # 组装 usb-image.raw 四分区镜像
    ├── grub.cfg                     # U 盘 grub 配置
    └── element/usb-provision/       # 自定义 DIB element:编排器 + systemd 服务
```

```bash
# 1. 构建环境镜像(上下文 = 项目根目录)
docker build -f build/Dockerfile -t usb-provision-build .

# 2. 构建 ramdisk(约 20 分钟;国内源已内置,可用环境变量覆盖回官方源)
docker run --rm -v "$(pwd)/dist:/out" usb-provision-build

# 3. 组装 U 盘镜像 —— 需要 loop 设备权限,在宿主机原生运行
#    (grub-bios-setup 的 loop backing file 不能在 overlayfs 上,故不在容器里跑)
OUT=$(pwd)/dist IPA_DIR=$(pwd) bash build/make-usb.sh
```

构建期自动完成的加固(重做构建无需手工重复):

- `element/usb-provision/install.d/50-usb-provision` 在构建期给 IPA 的
  `hardware.py get_os_install_device` 打补丁:优先读取编排器写入的
  `/run/usb-provision/target-device` 提示文件,避免 U 盘被当成装机盘;
- `make-usb.sh` 把预共享 `agent.conf`(含 `agent_token`)写入 config-2,并把同一值
  烧进 initramfs 的 `/etc/ironic-python-agent.d/` 作为 USB 枚举慢时的兜底;
- `usb-provision-config.service` 内置 30 秒轮询,等待 config-2 分区枚举完成。

> **只改 orchestrator / 配置文件?** 不必重跑 DIB:解包 initramfs 替换文件后重打包,
> 再更新 ESP 副本即可 —— `gzip -dc initramfs | cpio -id` 改完后
> `find . -xdev | cpio -o -H newc | gzip -9`。

### 换 ext4 的 ipa-images 分区

镜像单文件超过 4 GiB 时,把 `make-usb.sh` 中 p4 的 `mkfs.vfat` 换成
`mkfs.ext4 -L ipa-images`(编排器按卷标查找,文件系统无关)。

## 9. 已知限制

- 目标盘自动选择为"排除 U 盘后最大非可移动盘";多盘机器需精确指定时用 `target.device`
- FAT32 单文件 4 GiB 上限,大镜像需按 §8 改 ext4
- UEFI Secure Boot 未支持,目标机需先关闭
- 分区镜像要求镜像内自带 grub2(`install_bootloader` 在目标镜像内 chroot 执行)
- U 盘卷标(`config-2` / `ipa-images` / `ESP`)为 PoC 约定,改卷标需同步改编排器常量
- grub 菜单超时 3 秒自动进入装机;如需交互式选择,启动时按方向键
- 云镜像请用 **generic 变体**:`-kvm` 变体在 VMware 等非 KVM 虚拟化平台上装完无法启动(§7)
